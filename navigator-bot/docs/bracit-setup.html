BSAISL Migration Pathway Navigator · WhatsApp Cloud API

Setting up the Navigator bot on BRAC IT's WhatsApp account

Step-by-step setup for BRAC IT, from an empty WhatsApp account to the bot answering on BRAC's own number. It is based on the test setup we completed on 17 November 2026, including every problem we hit and how we fixed it.

Meta renames buttons often. Labels below match Meta's dashboard in November 2026. If a label differs, look for the closest match; the order of steps stays the same. All API calls use Graph API version v27.0.

0 Who does what

The bot is a small Python web service. It receives WhatsApp messages from Meta, looks up the answer in the BSAISL knowledge base (the country guides) and replies. Moving it to BRAC IT means BRAC IT owns every account and secret; the code does not change, only its settings file (.env).

BRAC IT

  • Meta app, WhatsApp account and phone number in BRAC IT's verified portfolio
  • Permanent access token, app secret, verify token
  • Server with a public HTTPS address
  • Billing, privacy policy page, publishing the app

BSAISL bot team

  • Bot code (git repository), Dockerfile, .env.example
  • Knowledge base and how to update it
  • Draft privacy policy text
  • Help with testing and fixing

Secrets stay with BRAC IT. The access token, app secret, verify token and the phone number's PIN go only into the server's .env and BRAC IT's password manager. Please don't send them to us by email or chat. Section 13 lists what we need back; none of it is secret.

Estimated time on BRAC IT's side: about 2 hours of Meta setup (parts 2–7 and 9–10), plus the time to get the server ready (part 8) and Meta's review of the display name, which can take from minutes to a few days.

1 Before you start

Have these ready. The first five block the setup if missing.

  1. Admin access to BRAC IT's verified business portfolio in Meta Business Suite (business.facebook.com), with two-factor authentication turned on for your Facebook account. Some token screens refuse to work without it.
  2. A phone number for the bot that is not used on WhatsApp or WhatsApp Business right now. A new mobile SIM is best. It must:
    • have a country code (+880) and be able to receive an SMS or a voice call, including from abroad (the code comes from Meta's systems);
    • be owned by BRAC (you will need it again to move or delete the number).
    If the number already has WhatsApp, delete that WhatsApp account first (in the WhatsApp app: Settings → Account → Delete account). Uninstalling the app is not enough.
  3. The display name people will see, for example a name that clearly belongs to BRAC. Meta reviews it and rejects generic names (like "Migration Help") that don't match the business.
  4. A server or hosting platform that can run a Docker container all the time and give it a public HTTPS address with a valid certificate (part 8).
  5. A privacy policy page on a public URL, ideally on a BRAC domain. We provide draft text (docs/PRIVACY.md in the repository) for BRAC's legal team to adapt.
  6. An app icon: any square image, 1024 × 1024 pixels.
  7. A payment method for WhatsApp billing, or confirmation that BRAC qualifies for Meta's non-profit exemption (part 7).

2 Create the Meta app

  1. Log in at developers.facebook.com with the Facebook account that is admin of BRAC IT's portfolio. If it isn't registered as a developer yet, click Get Started, verify phone and email, choose Developer and click Complete registration.
  2. Open developers.facebook.com/apps and click Create App.
  3. App details: app name, for example BRAC Navigator Bot, and a BRAC contact email. Click Next.
  4. Use case: select Connect with customers through WhatsApp. Click Next.
  5. Business: select BRAC IT's existing verified portfolio. Don't create a new one. Click Next.
  6. Requirements: probably none listed. Click Next, check the overview, then Create app. Enter the Facebook password if asked.

You land on the app Dashboard. Click Customize the Connect with customers through WhatsApp use case. The menu that opens reads Overview, then Basic setup with Step 1. Try it out, Step 2. Production setup and Step 3. Business verification. Keep Integrate with API selected (not "Become a Partner"). Older dashboards show the same pages as Quickstart / API Setup / Configuration.

Ignore Become a Tech Provider, Facebook Login for Business and Embedded Signup. BRAC is using its own account directly, so none of them are needed. Step 3. Business verification should already show as done because the portfolio is verified.

3 Create the WhatsApp Business account

Meta calls it a "WhatsApp Business account" (WABA) or, on newer screens, a "Messaging account". BRAC IT doesn't have one yet; it is created here.

  1. Click Step 1. Try it out.
  2. Under API Setup, find the Messaging account selector. If none is selected, click Create a WhatsApp Business account and follow the prompts (business name, time zone, category).
  3. Copy the Messaging account ID (also shown as WhatsApp Business Account ID). This is WHATSAPP_BUSINESS_ACCOUNT_ID.
  4. Meta also creates a free test number (+1 555…). You can use it to try everything below before the real number is ready: under To, open Manage phone number list, add a team member's WhatsApp number and enter the code it receives, then click Send message. A "Hello World" message should arrive. Reply "hi" to it, which opens a 24-hour window in which the bot may answer.

When the screen asks which WhatsApp accounts the app may access (a pop-up after Generate access token), choose Opt in to current WhatsApp accounts only and tick the new account. That token is temporary; the permanent one comes in part 5.

4 Add, verify and register BRAC's phone number

This happens in three stages, and the last one can only be done by API call: adding the number in the dashboard does not make it work yet.

4a. Add the number and set the display name

  1. Open WhatsApp Manager: business.facebook.com/latest/whatsapp_manager, select BRAC IT's portfolio and the new Messaging account.
  2. Go to Account tools → Phone numbers and click Add phone number. (Alternatively, in the app dashboard: Step 2. Production setup → Register your WhatsApp phone number.)
  3. Fill in the display name, category (for example Nonprofit or Education), a short description and the time zone (Asia/Dhaka).

4b. Verify the number

  1. Choose Text message (SMS) or Phone call. Keep the SIM in a phone with signal, and allow international SMS and calls.
  2. Enter the 6-digit code. The number now appears in the list. Click it and copy its Phone number ID. This is WHATSAPP_PHONE_NUMBER_ID. (The phone number ID is a long number, different from the phone number itself.)

4c. Register the number for the Cloud API (API call, required)

Meta's documentation states that registration can only be done by API, not in WhatsApp Manager or the dashboard. You need the permanent token from part 5 first, so come back here after part 5. Pick a 6-digit PIN; this becomes the number's two-step verification PIN. Store it in the password manager, because it is needed to move or delete the number later.

curl -X POST "https://graph.facebook.com/v27.0/<WHATSAPP_PHONE_NUMBER_ID>/register" \
  -H "Authorization: Bearer <WHATSAPP_ACCESS_TOKEN>" \
  -H "Content-Type: application/json" \
  -d '{"messaging_product": "whatsapp", "pin": "<6-DIGIT-PIN>"}'

Expected answer: {"success":true}. Then check the number's state:

curl "https://graph.facebook.com/v27.0/<WHATSAPP_PHONE_NUMBER_ID>?fields=display_phone_number,verified_name,status,name_status,quality_rating,code_verification_status" \
  -H "Authorization: Bearer <WHATSAPP_ACCESS_TOKEN>"

You want "status": "CONNECTED" and "code_verification_status": "VERIFIED". name_status shows the display-name review: APPROVED or AVAILABLE_WITHOUT_REVIEW is fine; PENDING_REVIEW means wait; DECLINED means choose another name in WhatsApp Manager.

Limits. The register call allows only 10 tries per number in 72 hours (error 133016 after that), so check the token and PIN before retrying.

If the display name changes later: after Meta approves the new name, run the same register call again, or the old name stays.

5 Create a permanent access token (System User)

The token on the dashboard's API Setup page expires within hours. The bot needs a token that belongs to a System User (an account for software, not a person).

  1. Open business.facebook.com/latest/settings and check BRAC IT's portfolio is selected (top left).
  2. Go to Users → System users and click + Add. Name: navigator-bot. Role: Admin. Click Create system user.
  3. Click the new user's name, then Assign assets:
    • Apps → the bot app → turn on Manage app (Full control).
    • WhatsApp accounts → the new account → turn on Full access → Everything.
    • Messaging accounts → Linked accounts, if the account is listed there → Full access too. Meta's docs say the token needs access to both the WhatsApp account and the Messaging account.
    Click Assign assets. Wait a minute and reload the page: both the app and the account must now appear under the user.
  4. On the same System User panel, next to Assign assets, click Generate token (it may read Generate new token, or sit under the ⋯ menu):
    • App: the bot app.
    • Expiry: Never. If only "60 days" is offered, take it and put a renewal date in the team calendar.
    • Permissions: tick whatsapp_business_messaging and whatsapp_business_management; also business_management if it is listed. Leave the others unticked.
    Click Generate token and copy it at once into the password manager. Meta shows it only once. This is WHATSAPP_ACCESS_TOKEN.

Check the token works (replace the two values):

curl "https://graph.facebook.com/v27.0/debug_token?input_token=<WHATSAPP_ACCESS_TOKEN>" \
  -H "Authorization: Bearer <WHATSAPP_ACCESS_TOKEN>"

Look for "is_valid": true, "type": "SYSTEM_USER", the two WhatsApp permissions under scopes, and "expires_at": 0 (never expires) or a date.

Problems we hit: the Generate token button doesn't appear until the app is assigned, which can take a minute or two after Assign assets (reload the page). Some accounts must turn on two-factor authentication first.

6 App secret and verify token

  1. App secret: in the app dashboard, left menu App settings → Basic, next to App secret click Show and enter the password. This is META_APP_SECRET. The bot uses it to check that every incoming message really comes from Meta.
  2. Verify token: a random string you make up. Meta sends it once when you connect the webhook (part 9), and the bot checks it matches. One way to make one: 
    python -c "import secrets; print(secrets.token_urlsafe(24))"
    This is WHATSAPP_VERIFY_TOKEN.

7 Billing

Since 1 October 2026 Meta charges for replies too: each phone number gets 1,000 free service messages a month, and from the 1,001st each reply is charged. Without a payment method on file, replies simply stop being delivered once the free 1,000 are used.

  1. In WhatsApp Manager (or Business settings → Billing and payments), open the WhatsApp payment settings and add a payment method (card or BRAC's billing arrangement with Meta).
  2. Check the non-profit exemption. Meta announced that eligible government and non-profit organisations keep free service messages beyond 1,000 a month until 31 December 2027. Meta decides eligibility. Ask Meta support (or BRAC's Meta contact) whether BRAC's account qualifies. When it applies, Meta's message-status data shows the pricing type paid_exempt.

We could not confirm the exact Bangladesh rates from Meta's rate card. Please check the current rates in WhatsApp Manager before the user-testing rounds.

8 Host the bot

Meta delivers each message to the bot's webhook address, so the bot must be running and reachable before part 9.

What the server needs

  • Always on. No platform that sleeps when idle: Meta retries late deliveries, and slow replies feel broken to users.
  • A public HTTPS address with a valid certificate, for example https://navigator-bot.<brac-domain>/webhook. Meta rejects self-signed certificates.
  • A reverse proxy (or the platform's router) sending traffic to the container's port 8000.
  • Outbound HTTPS to graph.facebook.com (WhatsApp) and to the AI provider (currently openrouter.ai; this may change after the model test).
  • A persistent folder for data/. It holds the conversation memory (kept 30 days, users stored only as scrambled codes) and the search index. The index can be rebuilt; the memory would be lost.
  • The knowledge base folder mounted read-only, with its path in KB_DIR. The bot never edits it.
  • Small resources are enough to start: 1 vCPU, 1 GB RAM, about 1 GB disk for the bot plus the knowledge base (the guides' text is small; the full research archive is 3.4 GB but the bot doesn't need it).

Deploy

  1. Get the bot repository from us (git). It will include a Dockerfile, .env.example and a README. These handover files are being finished after the AI model test; until then, part 8 can be prepared but not completed.
  2. Copy .env.example to .env on the server and fill it in:
    SettingWhere it comes from
    WHATSAPP_PHONE_NUMBER_IDPart 4bnot secret
    WHATSAPP_BUSINESS_ACCOUNT_IDPart 3not secret
    WHATSAPP_ACCESS_TOKENPart 5secret
    META_APP_SECRETPart 6secret
    WHATSAPP_VERIFY_TOKENPart 6secret
    GRAPH_API_VERSIONv27.0not secret
    PUBLIC_DOMAINThe server's public address, without https://not secret
    KB_DIRPath of the mounted knowledge base foldernot secret
    LLM_BASE_URL, LLM_API_KEY, LLM_MODELThe AI provider BRAC approves (question group C)key is secret
  3. Build the search index from the knowledge base, then start the bot (the exact Docker commands will be in the README): 
    python -m app.kb_index      # builds data/kb.sqlite from KB_DIR
python run.py               # serves on port 8000
  4. Check from outside: open https://<PUBLIC_DOMAIN>/health. It must answer {"status": "ok", "kb_built_at": …, "kb_sections": …}.
  5. Check the webhook answers Meta's handshake (use your verify token): 
    curl "https://<PUBLIC_DOMAIN>/webhook?hub.mode=subscribe&hub.verify_token=<WHATSAPP_VERIFY_TOKEN>&hub.challenge=12345"
    It must print 12345. With a wrong token it returns error 403, which is correct.

When the knowledge base is updated (copy or git pull into KB_DIR), run python -m app.kb_index again. The new index replaces the old one in one step, so the bot keeps running.

9 Connect the webhook

9a. Callback URL and verify token

  1. In the app dashboard: Use cases → Customize → Connect on WhatsApp → Step 2. Production setup, section Configure Webhooks. (Older dashboards: WhatsApp → Configuration → Webhook → Edit.)
  2. Callback URL: https://<PUBLIC_DOMAIN>/webhook
  3. Verify token: the WHATSAPP_VERIFY_TOKEN value.
  4. Leave Attach a client certificate off. The bot checks Meta's signature on every message with the app secret instead.
  5. Click Verify and save. It must show success. If it says the URL could not be validated, the bot isn't reachable or the token differs (see part 12).

9b. Subscribe to messages

The Webhook fields list appears only after a successful Verify and save, under the same section. Find messages, set it to Subscribed (toggle, or Manage → Subscribe). The other fields can stay as they are.

9c. Link the app to the WhatsApp account (API call)

On our test account, messages kept going to Meta's own sample app ("WA DevX Webhook Events 1P App") instead of ours, because the dashboard had not linked our app to the WhatsApp account. Check, and link if needed:

# Which apps receive this WhatsApp account's messages?
curl "https://graph.facebook.com/v27.0/<WHATSAPP_BUSINESS_ACCOUNT_ID>/subscribed_apps" \
  -H "Authorization: Bearer <WHATSAPP_ACCESS_TOKEN>"

# If the bot app is not in the list, add it:
curl -X POST "https://graph.facebook.com/v27.0/<WHATSAPP_BUSINESS_ACCOUNT_ID>/subscribed_apps" \
  -H "Authorization: Bearer <WHATSAPP_ACCESS_TOKEN>"

The POST answers {"success":true}; run the GET again and the bot app's name must be listed.

10 Publish the app

Without this, the bot gets no real messages. While an app is unpublished, Meta only delivers the test events sent from the dashboard, not messages from real people, not even from the app's own admins.

  1. Left menu Publish. It lists what's missing.
  2. Click Go to app settings (or App settings → Basic) and fill in:
    • Privacy policy URL: BRAC's public privacy policy page (draft in docs/PRIVACY.md; it covers what the bot stores, that it uses Meta and an AI provider, the 30-day deletion, and how to ask for deletion).
    • App icon: the 1024 × 1024 image.
    • Category: for example Education.
    Click Save changes.
  3. Back on Publish, open Connect with customers through WhatsApp and check nothing is flagged as missing.
  4. Click Publish. For BRAC's own WhatsApp account this needs no App Review; it goes live straight away.

11 Test

  1. From any WhatsApp phone, send "hi" to BRAC's bot number. The bot should reply within a few seconds and ask which country the person is asking about.
  2. Send "Saudi Arabia", then "medical check cost". The bot should answer about the Wafid medical check.
  3. Watch the bot's log: each message appears as Message wamid… received (text). Lines like POST /webhook 200 without "received" are Meta's sent/delivered/read updates, which the bot ignores on purpose.
  4. Send "delete my data". The bot confirms the user's history was deleted.

Then tell us, and we run the full test set (41 questions in Bangla and English) against BRAC's setup.

13 What to send back to us

None of these are secret. Please send them once the parts are done:

  • The bot's WhatsApp number and its display name, and the display-name status (name_status).
  • WHATSAPP_PHONE_NUMBER_ID and WHATSAPP_BUSINESS_ACCOUNT_ID.
  • The public webhook URL.
  • Confirmation of each part: 4c registered, 9a verified, 9b subscribed, 9c linked, 10 published, 7 billing or exemption status.
  • The token's expiry date (from the debug call in part 5).

Do not send: the access token, app secret, verify token, phone PIN or AI key. If BRAC IT wants us to help on the server itself, let's agree a secure way first (for example adding our developer to the app as a Developer role, or a screen-sharing session).

14 Meta rules that apply to this bot

  • AI chatbots: Meta's WhatsApp Business terms (in force since 15 January 2026) ban general-purpose AI assistants on the platform. Our bot is allowed because it is limited to BRAC's migration information: it refuses off-topic questions, and we'll keep it that way.
  • Human help: Meta's business messaging policy requires automated chats to offer a clear way to reach a person. BRAC needs to name a helpline, email or office the bot can point to (question D3).
  • Only reply, don't broadcast: the bot answers people who write first. Messaging people first would need their opt-in and approved message templates, which we don't plan.
  • No ID numbers: the bot never asks for passport, NID, bank or card numbers.

15 Questions for BRAC IT

Answers to these decide how we finish the handover files. Short answers are fine.

A. Hosting and deployment
  1. Where will the bot run: BRAC's own servers, a cloud provider (which one), or a container platform?
  2. Can you run it from a Dockerfile we provide (with docker compose)? If not, what do you need instead (a plain Python service, a Kubernetes manifest, something else)?
  3. What public HTTPS address can the bot have (a subdomain of a BRAC domain?), and who manages its certificate and reverse proxy?
  4. Does the server allow outbound HTTPS to graph.facebook.com and to an AI provider's API?
  5. Can it keep a persistent folder for the bot's data, and is it backed up?
  6. Do you want a separate test (staging) setup and a live setup, each with its own WhatsApp number?
  7. How do you deploy updates: CI/CD from a git repository, or by hand? Who restarts the bot after a knowledge-base update?
  8. What do you use for logs and monitoring, and who gets alerted if the bot stops replying?
B. Meta and WhatsApp
  1. Which phone number will the bot use? Is it a new SIM, and does it currently have WhatsApp on it?
  2. What display name should users see, and has BRAC used it on WhatsApp before?
  3. Who will be the admin of the Meta app and the system user, and who keeps the PIN and token?
  4. Can you add our developer to the app (App roles → Developer) for testing, or should all testing go through you?
  5. Will BRAC add a payment method for WhatsApp, and can you ask Meta whether BRAC qualifies for the non-profit exemption?
  6. Do you need WhatsApp's local data storage option? (Bangladesh is not one of the offered regions; the nearest are Singapore and India.)
C. AI provider
  1. Is BRAC IT OK with using OpenRouter (one key, many models), or must it be a direct contract with one vendor (Anthropic, OpenAI, Google, Azure)? Changing it is a settings change only.
  2. Who pays for the AI usage, and is there a monthly budget limit we should design for?
  3. Are there rules on sending migrants' questions to an AI provider outside Bangladesh (for example, only providers that don't store or train on data)?
D. Data, privacy and support
  1. Is 30 days the right retention for conversation history, or does BRAC's policy require something else?
  2. Where will the privacy policy be published, and who in BRAC approves its text?
  3. Which helpline, phone number or office should the bot give people who need a human (for example BRAC's Migration Programme)?
  4. Does BRAC need a security review or data-protection sign-off before the bot goes live?
E. Code, knowledge base and timeline
  1. Where should the code live: BRAC IT's GitHub or GitLab organisation? Should we open pull requests there, or will you import our repository?
  2. Any constraints on language or framework (the bot is Python 3.12+ with Flask and SQLite)?
  3. Where should the knowledge base repository live, and who besides the BSAISL team may update it?
  4. The Navigator is due on 3 December 2026 with user-testing rounds before then. When can the number, hosting and webhook be ready?
